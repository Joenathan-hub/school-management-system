# Contrast audit

Every foreground/background pairing the interface actually creates, measured in
both themes against WCAG 2.1: **4.5:1** for text, **3:1** for non-text components
(focus rings, chart marks, status dots).

Generated by `tools/UiAudit.java`, which reads the two token sheets and resolves
each pairing through token-to-token references, so the numbers below are the values
the application will use and not a restatement of them.

Reproduce:

```bash
javac -d /tmp/uiaudit tools/UiAudit.java
java -cp /tmp/uiaudit UiAudit .
```

The command also checks that no colour literal exists in Java source and that the
light and dark sheets define the same variable names; it exits non-zero if any
pairing fails or the sheets disagree.

## How to read the verdicts

* **PASS AAA** — 7:1 or better. Used for primary text and for the rail.
* **PASS AA** — 4.5:1 or better. Every piece of real text in the interface is at
  least here.
* **PASS (non-text)** — 3:1 or better, which is what WCAG asks of a graphical
  object that has to be seen to understand the content: focus rings, chart bars,
  the notification dot, the progress fill.
* **ACCEPTED (see notes)** — measured and printed, deliberately below the standard,
  with the specific reason listed under each theme. The tool exits non-zero if a
  pairing fails *without* a reason, so this list cannot grow by accident.

## Coverage and limits

Covered: every text on every surface, the semantic badge/banner/toast pairs in all
five tones, all button variants, the rail (text, muted text, active item, brand
tile, brass indicator), the top bar, chart series against each other and against
the card, focus rings against both surfaces, the progress fill, the notification
dot and the severity of the hairlines that separate surfaces.

Not covered, and why:

* **Disabled controls.** Their text is dimmed by the control skin rather than by a
  token, so there is no pairing in the sheets to measure. If you want disabled text
  audited, give it a token and it will be picked up.
* **Text over the avatar gradient.** Measured against the gradient's first stop
  (the brand colour), which is its lightest end in both themes.
* **The scrim.** It is a translucent overlay above the dialog, above the command
  palette and above nothing else; the dialog and palette surfaces are audited
  against their own backgrounds.
* **The base theme's own controls** (combo popups, date pickers, scrollbars). Their
  palette is redirected through the token bridge — which is what makes them match —
  but their individual colour pairings live in AtlantaFX, not in this repository.
